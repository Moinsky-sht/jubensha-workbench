# 第二版：模型与项目记忆

## 本轮实现

| 入口 | 用户操作 | 数据行为 |
| --- | --- | --- |
| 设置 · 模型连接 | 搜索、测试、设为默认、同步目录 | 按火山目录识别文本生成能力，排除下线及非文本模型；每六小时同步 |
| 故障切换 | 启用或关闭 | 每轮最多尝试三个模型，每个模型的网络或限流故障最多重试两次；预算仍逐次核对 |
| 设置 · 项目检索 | 查看索引进度、发起更新 | SQLite 保存项目独立的向量，后台分批更新，正文稳定编号映射到引用 |
| 搜索 | 按含义查找当前项目 | 原文匹配与向量召回合并，硅基流动重排，失败时保留原文匹配结果 |
| 对话 · 生成依据 | 展开引用与实际模型 | 引用绑定本次输入，失败路由与实际结果留在任务记录中 |

主界面保持三栏。模型目录限制高度，详细标识不占据每一行；自定义连接保留原入口。搜索不在每次按键时调用付费接口，按含义查找由用户发起。引用按需展开，不重复粘贴整篇新稿。

## 预置与边界

服务端读取参考项目中火山文本、硅基流动向量与重排所需的环境变量。密钥不进入浏览器、源码包及交付文件。现有 SQLite 加载 sqlite-vec 扩展，以项目过滤后的余弦距离完成检索；目前采用精确检索，单项目最多两万个片段。没有增加独立向量服务器。

正式事实继续来自项目对象。历史讨论只检索最近二百条消息，并标注未确认为设定；附件中的历史指令不触发操作。索引写入前比较项目及对话指纹；检索时剔除原文已变化的旧向量结果。对话引用可辅助召回，不取代锁定约束与当前对象。

目录可见不代表账号已开通所有模型。接口测试状态独立保存，自动路由暂避失败连接并排除退役模型。默认优先 Seed 2.1 Turbo、GLM 5.3 Flash、DeepSeek V4 Flash；特殊用途模型仍需满足统一修改协议。

## 下一轮验收与优化

浏览器访问恢复后，逐项验收十个空间、对象切换、对话分支、输入恢复、选区修订、锁定冲突、导入导出、三种主题、390px 窄屏及键盘焦点。根据实际页面修正可读性与操作距离，再核验打印分页。

确认云主机实例与 DNS 管理入口后，使用独立目录部署，挂载持久化数据，启用 HTTPS，保留迁移前备份。生产域名由部署者自行指定；仓库内仅准备部署配置，不包含任何真实云资源与解析记录。
