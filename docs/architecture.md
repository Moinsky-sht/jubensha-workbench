# 实现约定

## 数据入口

`shared/domain.ts` 定义对象、可编辑字段、富文本与操作白名单。浏览器不直接写数据库，模型不输出 SQL 或脚本。

`server/projects.ts` 的 `applyChange` 是故事内容写入入口：解析全部操作 → 对原版本模拟 → 校验正文与引用 → 判断审阅 → 事务提交对象、快照及变更。每个变更集的执行标识唯一。版本冲突保留原生成依据，旧文本不覆盖当前稿。`resolveChange` 再次检查当前版本和原文；`undoChange` 保护后续已经编辑的对象。

实体引用使用稳定 ID；排序只更新顺序值。角色认知、共同事件和正文是不同对象／字段，任何一处变化都不会靠全局字符串替换传播。上游变更通过引用图标记待检查，模型明确提供联动操作时一起提交。

素材文件不可写；提炼结果另建条目。规范、任务、项目版本、对话历史均在服务端保存，模型切换重新编排上下文。

## 后台执行

API 把输入版本、规范内容、模型配置、范围和历史快照写入 `jobs`。Worker 独立运行，按依赖、项目串行保护和连接并发限制取任务，全局初始并发为 2。事件流只报告状态与版本，未完成的模型文字不进入正式草稿。

每个实际 HTTP 请求先预留用量；并发请求、格式修复和网络重试共用预算。停止后通过 AbortController 取消请求并禁止写入。进程重启保留已完成内容，运行中任务转为暂停；若变更已经提交而任务还没标记完成，通过同一个执行标识找回结果。

一个任务失败不回滚其他项目。重试生成新记录，同时更新尚未运行的依赖指向；同一批次继续使用冻结的规范和模型配置。导出、检查等无模型任务不消耗调用预算。

## 交付边界

`audience` 决定可纳入的对象，`safeEntity` 再过滤作者字段。正式文件绑定固定项目版本，只取定稿对象；原始素材、未采用讨论和 API 配置不会进入玩家包。此边界保证对象／字段隔离，不声称理解正文里每句话是否剧透。

本版用通用条目及引用表达时间线、揭露条件和资源。人物关系图、幕表、场景排序、演绎时段和冲突检查均读取这些对象。关系的详细流转目前通过条目和关联编辑，没有额外的可视化条件编排器。

## 文件布局

- `src/`：工作区、长文编辑、对话、任务和设置。
- `server/`：故事事务、模型适配、导入导出、审校与 Worker。
- `shared/`：浏览器与服务端共用的数据协议。
- `server/migrations/`：递增迁移，不就地更改已应用版本。
- `scripts/`：备份与迁移恢复。
- `tests/`：领域回归、真实 HTTP 链路和恢复测试。

适用单用户私有运行。下一轮需要实际浏览器回归、真实模型样本评测、Word 富文本保持和线索打印校样；不要把接口模拟通过当作这几项已经验收。
