# 第三版：主创智能体

## 使用入口

新建项目只收集名称、核心想法、题材、玩家数和时长。作者选择整本初稿或故事框架后直接进入生产进度；进入空白项目适用于导入旧稿或完全手动搭建。

项目内“主创”保留同一入口。作者可以修改创作目标、选择产出深度、展开阶段计划、暂停、继续或停止任务。模块目录仍用于审阅和局部对话，不再承担启动整本生产的负担。

## 工具与调度

服务端注册素材、立意、设定、人物、结构、线索、正文、演绎、审校和交付十个工具。每个工具限定模块、输出对象、依赖、运行模式和专属要求。模型返回变更操作，服务端验证后写入。

八个阶段依次完成创作简报、立意、世界与人物、结构、线索、正文与演绎、审校、交付核对。世界和人物同时运行；正文按玩家拆分，演绎按幕拆分，两组工作共享已提交的事实底座并受并发上限约束。

同一阶段固定输入版本，全部结果合并成一个变更集。生成期间发生人工编辑时，该阶段暂停并保留候选，不覆盖新稿。模型不能删除对象、解锁内容、自行定稿或写入工具范围以外的数据。

## 继续生产

再次启动时，系统先检查当前项目。已有的创作简报、立意、世界事实、玩家角色、幕场结构和线索链直接沿用；角色已有对应正文、某幕已有对应演绎时也跳过该工作项。缺失部分继续生成，审校和交付核对始终依据最新版本执行。

这个行为用于从框架继续到初稿、从中断位置恢复和补齐局部缺口。需要推翻上游时，作者先在对应模块对话中明确修改，变更服务会标记受影响的下游内容。

## 进度与错误

进度以故事生产环节展示。每个步骤显示等待、运行、完成、失败或待审状态，以及实际使用的模型和结果摘要。接口细节与 JSON 保留在追溯数据中。

每次生产设有限调用量。网络和限流最多重试两次；结构错误只修复一次。备用模型按预置顺序切换并记录路径。独立阶段已经提交的成果不会因后续失败消失。
