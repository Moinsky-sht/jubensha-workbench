# 来源整理与修改协议

## 全量检索的单位

先盘点收到的文件、轮数、字数、校验值，分离用户要求、引用的原稿/参考、助手回应。逐轮登记「原文—意图—范围—依据—修改类型—验收条件—后续覆盖」。助手自称“已根据附件”“3000字”“已保留全部内容”都不是验证证据。

重复轮次保留原位置并标引用关系，不算新的独立偏好；新文件包含旧文件时保留映射，不能把同一要求算两遍。提炼时覆盖短句纠错、否定、命名、诗句和数量要求，不只读长提示词。对“需要修改：1”这类残缺输入标缺失，不猜测后半句。

脚本 `intake.py` 适配本案例导出格式，保留每轮 prompt 及其后完整导出片段；后者可能包含下一段会话标题，不应直接当作纯助手定稿。脚本完成不等于已完成语义阅读。其他导出格式先确认发言边界，不能用此格式的正则强行解析。

## 范围化覆盖

为规则保存稳定ID、字段、值、角色/幕范围、来源轮次、状态、被谁覆盖。状态可以是 confirmed（用户明确要求/采用）、proposed（助手建议）、conflict（当前证据矛盾）、missing（引用未收到）。用户的历史 confirmed 仍只在历史项目内有效。

- 新要求只覆盖同一字段和范围。改名字不改变身世；“三倍”不允许偷加揭密；后来写另一角色不继承上一角色禁姓。
- 用户引用旧文不表示重新确认引用中的全部事实。判断引用用于润色、格式参考、情绪参考，还是作为当前完整依据；正文与本轮明确修订冲突时采用本轮修订。
- “抛弃之前”“整体改设定”“新增一幕”建立版本分叉或迁移记录；不能按最新一条回答直接拼接旧幕。
- “前两幕已经定稿，按上传续写”但附件缺失时，可分析已有全局与待解因果，不能声称已经准确接续定稿原句。
- 修改角色身份、时代制度和时间线属于设定变更；旧场景须重新评估动机、通行资格、知情与结果，不只替换名词。

## 修改类型与交付合同

|类型|保留|允许改变|验收重点|
|---|---|---|---|
|续写|最后定稿结尾、人物状态、未揭真相|授权后续事件|接点、时间与行动因果|
|扩写|指定段的事件顺序、归因、结局|已有行动的过程、对话、反应与细节|以原段为基线；新增事件需有授权|
|润色|事实、知情范围、人物立场|句法、节奏、意象、措辞|不能用“更动人”改写设定|
|增写|既有正文及相邻状态|要求数量/位置的新事件|新段作用不同且接入主线|
|局部替换|非目标段原文|目标段所需内容|只改授权范围，给定位或替换块|
|重写/版本迁移|明确要求继承的核心|被授权范围内的结构与内容|标明废弃内容及下游重审范围|
|命名/一句话补全|约定字数、保留词、语义|指定空缺|不要附带整幕重写|

生成前建立简短合同：工作版本、修改范围、原段路径/定位、不得改变的事实、目标字数与口径、新增情节权限、返回格式。篇幅很短时合同留作内部记录，不必打断用户。若用标记拆分正文，先明确计数包含哪些内容。

## 修订闭环

要求 → 改动片段 → 影响文件 → 检查结果 → 最新工作入口。出现同类错误时补一个能检测它的约束，不无差别增加所有项目负担。修改期间保留旧版，重复失败仅重做受影响段；若核心前提缺失，不用不断润色掩盖矛盾。

扩写基线必须是用户指定原段，不能用自己刚缩写的版本作分母。约数可设合理区间并说明；“至少3000字”是下限，不能自行放宽。没有基线时不能报告倍数已达标。


# 多角色、双时空与信息联动

## 最小设定模型

按复杂度启用下列记录；简单单场不必填全部。

|记录|关键字段|解决的问题|
|---|---|---|
|人物实例|稳定ID、称谓/旧名、生效版本、玩家/NPC、时代、肉身、念源、记忆来源|同名不等于同一在场个体|
|世界规则|规则ID、触发、效果、方向、代价、失效、例外依据|共享痛觉、献祭、返程不能随场景改变|
|事件事实|事件ID、时间地点、真正行动者、受益者、见证者、结果|功劳与伤害不能串人|
|角色认知|事件ID、角色ID、知道/误认/怀疑、证据、更新时点|合理误会不变作者事实|
|信息释放|内容ID、允许读者、最早幕、触发证据、可呈现表象、禁揭内容|角色本与幕后真相隔离|
|物件实例|物件ID、来源、版本/时间、持有人、转交、使用与回收|双时空同件/两件数量混乱|

同一个事件只维护一份客观事实，各角色本分别生成其当时可见的一面。不能把每个人的主观叙述直接合并成真相。

## 机制必须带方向与条件

例如「慕苍劫受伤 → 云栖禾感痛」与「云栖禾受伤 → 慕苍劫感痛」是两条规则；前期仅前者、后期才反转，就记录切换触发。枯萎症、吸取灵力导致的虚弱、共享伤痛是不同原因，不得看见“疼”就套一条机制。沈念线明确排除共享痛觉，关联人物也不能自动继承。

轮回分别记初始人生数、重生次数、当前第几世，不把“78次重生”与“79世”直接视作冲突，也不能未经依据擅自算出新计数。过去人物肉身进入现在、念源附身与本来就存在的当代人物，具有不同通行资格、认亲方式与记忆边界。

## 错认与隐性守护的四层写法

例：事件由魁完成；女主以为是当前李慕白；当前李对此不知情；玩家只读到有歧义但可信的表象。将四层分别填写，不写幕后镜头直接揭答案，也不能使当前李提前知道魁的牺牲。当前李真实的关心仍有他自己付出的证据，不能把他的所有好都转给魁。

伏笔要记录「现在能观察到什么」与「后来什么证据改变解释」。不是每段都加血味、黑影或不祥暗示；过密提示会提前耗尽谜底。幸福阶段可有真实幸福。反转改变部分意义，不必使全部经历失效。

## 跨本变更传播

一条修改完成后查：世界规则 → 共享事件 → 每人当时所知 → 各角色本 → NPC流程 → 线索/物件 → 后段回收。标注需重审的受影响节点，禁止自动把未审的旧稿算进当前已通过版本。

- 插入新第二幕：原幕使用稳定ID，显示幕号后移；同步死亡、能力发现、道具获得、演绎转场与揭密编号。
- 女尊三夫四君改为巫女候选禁见外男：重写相亲/入赘/婚约冲突的法律前提与人物动机；不是简单删一句世界观。
- “亡国皇帝”改为“未登基、被父皇囚禁的太子”：回查亡国、皇后身份、囚禁来源、药人归因和所有回忆称谓。
- 当前身份多出一人：晨微、过去晚意与清鸾同时存在，清鸾对晚意的熟悉不能自动用于晨微。进府理由必须独立成立。
- 玩家角色不参加NPC流程：可以在其本中记录共同历史或设计双方自由互动，不能给其安排必须照念的NPC脚本。

## 因果推演

对关键决定写出：目标、现有信息、可选行动、资源限制、实际选择、结果、后果。反转依赖规则须提前有可核对的铺垫。特别查“为何不能用更容易的方法”“救得出这次为何不能直接终结反派”“杀错对象为何仍能触发返程”。没有确定答案登记待解，不用新增万能法宝或“天道注定”遮蔽。


# 正文、关系与演绎

## 叙事与文风

先提取用户认可版本的节奏和叙事机制：自然口语骨架、具体日常处境、长短句变化、自嘲与落差、少量准确古风意象。不能把“御姐”“搞笑男”“妻管严”“凶但爱他”等作者标签直接反复写进正文。不要用“气场全开”“深情入骨”替代行为，也不要用密集排比和感叹号制造强度。

参考只抽象为结构功能与节奏，换掉生活细节、事件路径、意象和句式；不是人名替换。历史要求“不可出现素材相同语句”适用于相应项目；拿到素材才可检查匹配，没有原文就说明无法完成逐句比对。

第二人称只规范当前人物的叙述，不改对话中正常自称。角色推断用“你以为/你怀疑/从他的说法看来”等限定；不能跨入NPC未表达的内心。对幼年往事使用符合年龄的欣赏、羞怯和亲近，成年后的亲密关系另行建立时间依据。

## 场景卡

字段：场景ID、所在幕、视角、地点/时间、进入状态、人物当下欲望、阻力、行动与回应、转折、新增信息、关系变化、关联任务/物件、离开状态、目标字数。

优先把恋爱写进共同任务：治疗时的信任、训练时的分歧与进步、任务前后照料、争执后的补偿。严厉的具体理由可以是危险或责任，但关爱要有行动证据、双方回应和边界；不要自动把辱骂殴打升级当深情。

扩写一个场景时增加起因→尝试→反馈→调整→余波；两则故事可以共享训练或出行主线，但要分别产生不同关系变化。若删去甜蜜段落丝毫不影响关系、任务或后续选择，重新连接主线。

人物反差有稳定原因：身份端庄而私下嗜酒，只是可选案例。用藏酒、被发现后的应对、分享方式展现可爱，保持其能力与尊严。兄妹交流既表现亲密，也呈现双方信息差，不能把妹妹纯粹作为主角上进的道具。

## 羁绊与回收

物件卡：ID、形态和识别细节、来源、送出理由、获得场景、约定动作/语言、保管位置、再次使用、揭密关联、终局变化、舞台实现。

建议路径是建立→日常复用→意义改变→选择/终局回收，具体次数服从剧情。梳头可以由日常亲密转为记忆恢复的证据；证据是角色做出了本不该知道的动作，而不是作者直接宣告对方全知。幸福时的赠礼可以出于单纯偏爱，不因后来惨剧而把当时写成灾难现场。

## 可运行流程卡

每张记录：读本结束点、玩家已知/未知、NPC进场目的、人物当前任务、触发条件、预估时长、场地/道具/音效、关键台词意图、玩家可采取行动、分支回应、获得信息、退出信号、下一幕入口。

至少处理主动配合、沉默、不愿执行、意外提问四类反应。用可替代的台词和线索推进，不能假定玩家一定说固定句子。玩家应有表达、判断或行动的空间，不只是听NPC讲完。

危险或难现场实现的动作（例如扇国师一巴掌）采用借位、音效或象征动作；明确由谁完成、谁见证，不能用“机缘巧合完成了”跳过核心互动。历史回忆与现场可选动作分别标注。NPC不说出本幕揭密上限之外的信息。时长是估计，真人试跑后再校准。


## 情感丰富度与人物分寸

角色需要独立愿望与行动权：识字作诗、被家人尊重、离开束缚、兑现承诺等。支持她的愿望可以比单纯救命更能区分恋人；不把所有关爱写成同一种牺牲。每条关系记录「最初吸引—相处证据—矛盾—修复—选择」，允许甜蜜、轻松、尴尬、钦佩、信任和悔意交错，不因是情感本就每幕高强度虐恋。

同一人在不同关系中的善恶可以不同。坏人爱某人不等于其伤害全是误会；好哥哥与恶哥哥不能因称谓相同串设定。误会解除之后保留受伤一方的回应、重新建立信任的过程，不用一句“其实为你好”抹平。

新旧恋人对照要让两人各有真实、独有的付出与局限，不把当代角色写成毫无价值的替代品。若此幕要求真正的冷酷，就写冷酷，不自动补深情尾巴。女主也可以有过失和补偿，不把她所有难处都归为被动受害。

日常场景同时服务后续不等于处处提前预告悲剧。可以先让玩家喜欢某个真实的习惯，再在后幕通过物件、动作或选择回收。高光依赖前面的经历，不能直接规定玩家“此刻必须痛哭”。

## 读本与现场的接口

每段标注是历史回忆、读本时刚发生、还是读完后待发生。若让NPC重演书内经历，明确这是记忆再现/新视角补充，避免玩家重复做已经完成的唯一选择。故事叙述、演绎剧本与作者提示是不同文体；用户要第二人称角色本时，不用“某某：（动作）台词”形式充数。

流程卡记录实际参与者类型、进退场、手持物件、其他玩家等待时的活动、信息交接。共用NPC要核对同场时段是否冲突；灵体/分身/新旧同脸人物需确定可用演员或可辨识标记，不能默认有无限演员和特效。

亲密、受伤与威压情节先区分角色历史与现场动作。涉及亲密描写时明确成年阶段；现场按已约定的互动边界安排，以可替代的非接触表达完成情绪与信息，不能因书中发生过就要求玩家照做。拒绝互动的分支仍能获得推进必需信息。


# 质量门与验收

## 阻断项：修复后再标 ready

- 玩家/NPC错位，“你”指错人；同一世界事实在多个本中互相冲突。
- 采用已被覆盖的旧任务、旧家族关系，或把缺失附件当已读定稿。
- 玩家无来源地知道隐藏真相；把怀疑写成事实；当前幕越过揭密上限。
- 时间循环、献祭、回归、记忆恢复的条件互相矛盾，关键规则到结局才临时出现。
- 核心任务没有实际执行路径，流程只让玩家旁观，或依赖唯一固定回应。
- 明确要求的正文/流程/大纲缺项；实际篇幅与目标差距未说明；玩家包泄漏作者答案。

## 内容审读

逐场问：为什么此时发生？角色为何这样做？玩家从哪里得知？情感或局势有什么变化？下一场为何成立？逐个反转沿线回查至少一个既存伏笔和一个足以改变判断的新证据。

双向检查：全局真相能否解释每幕现象；玩家按现有线索能否形成预期认识（包括合理误解）。对穿越分别列原时间线、目标时间线、魂/念源与肉身、历史记载、返程条件、可改变与不可改变事件，不能仅靠“天道如此”遮盖漏洞。

风格检查：是否贴标签、滥用高强度修饰、同样的“嘴硬—脸红”反复出现；扩写是否产生新行动而非重复内心。批次间比较核心冲突、情感事件和回收结构，不只查文本重复。

素材可得时做相同长句和连续表达的人工对照；自动相似度只能提示复查，不能证明原创。不要把未提供的参考文本当已核验材料。

## 验收记录

记录项目/版本、检查范围、实测长度和口径、通过项、发现问题、修复位置、剩余问题、试跑状态。文本 ready 与真人 playtested 分开。

工具边界：batch.py 检查 manifest、路径、文件存在、正文去空白字符数、显式字面合同、遗留阻断项与 ready 的冲突；不检查剧情、视角、表演质量、原创性或人物感情是否成立。这些必须审读，不得用“脚本通过”替代。


## 从历史纠错形成的回归场景

用于真实任务的定向审校，不要每次把全部案例套给新本。

|输入约束|必须识别的失败|通过时应看到|
|---|---|---|
|假装哑巴，仅润色开口段|药物治愈哑症；人生初次听声|表面误解与实际选择开口分开|
|魁暗助，当代李不知情，女主误认|幕后视角直揭；当代李主动替魁掩护|四方信息边界清晰，真心各有证据|
|只扩原段三倍、禁止新情节|添新凶手、花海揭密或新法宝|原事件细化，基线和实测长度可核|
|参考仅文风，当前叫李慕白|谢某、谢家、参考昵称残留|姓名亲缘与参考隔离|
|沈念无共享痛觉，沈临好人|从剑灵线复制能力/恶兄|本线机制和关系独立|
|新增第二幕，旧二变三|两次同一死亡、两次初识能力|稳定场景ID与显示幕号同步|
|晨微多出一人，旧晚意仍在|姐姐自然认晨微为原妹妹|通行、认亲、知情有依据|
|旧太子被父皇迫害，双方一直相爱|太子突然成药人加害者|加害与保护归因保持|
|凤凰于飞，总八字|补成九字或长段解释|固定四字+新增四字|
|婚礼尚幸福的双生锁|提前写成绝境遗物|赠礼与当时情绪一致|

每次任务只勾选实际适用项；将它们转换为该项目的具体约束ID，避免案例姓名进入无关正文。

## 真人试跑记录

记录真实阅读/演绎耗时、玩家能否复述关键关系、哪个线索引发错误判断、沉默/拒绝时是否继续、NPC能否兼场、物件是否完成转交回收。哭不哭不是唯一合格标准。标明测试人数、条件、版本与改动；未试跑不推断实际时长、满意度或量产成功率。


# 命名、诗句与素材使用

本模块来自大量短提示词纠错；只在相关任务使用。

## 命名

先记录对象、字数、禁用姓/字、读音倾向、世界内身份、必须保留的名称、组合语义。候选反馈只改变被否定的部分：笔名定为“不归”就不要继续改笔；花名要求两个字就不能给三字花名。人物要像人物名、物件要像物件名，不因悲剧结局让所有名字都直白预告死亡。

将拒绝候选与已采用名分开；“这个意思可以，声音不好”保留语义换读音。“不灭”曾被要求换名，后续用户明确在诗里使用“不灭花”时，应承认该范围内的新采用，不永远按旧否定处理。

名字、口癖与参考角色不一起迁移。使用别人的人物作气质参考时，当前人物自称不能残留“谢某”“陆相执”或原参考昵称。

## 对仗与定长补全

固定字/词、总字数、上下句结构、真正要表达的意思先写清楚，再输出约定数量的成品。例：“凤凰于飞”四字固定，总共八字，新增只能四字；不要用一段解释替代。要求“回首发现深爱”，不能只写“共白头”；要求恶人极恶这一句，不自动加“唯独对你温柔”转折。

对仗检查字数、词性对应、句法位置、意象关系和语义；押韵说明采用现代读音还是指定韵书，不未经核验宣称“完美合律”。少量候选即可，用户要求一句就优先交一句。

## 引用与原创

区分“原诗引用”“化用意象”“原创拟古”。引用作品、作者、诗句出处需要可核验依据；无法核实时不编出处，可改为原创并明确标注。人物叫李慕白不表示他就是历史李白。架空婚俗可以原创，不能说成真实民俗史实。

参考材料用于抽象叙事功能、节奏和情绪路径，再重新设计具体事件、细节、意象与表达。用户说“洗一下”也不能仅换人名、近义词或照搬独特事件链后宣称原创。若要求完全不出现相同语句，要在得到参考全文后对照，约定是否豁免固定古诗、通用词语与既定专名；相似度检测不能证明版权或原创结论。
